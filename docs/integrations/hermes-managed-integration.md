# CCEM 托管 Hermes 集成

初版实现：2026-09-10；多渠道、多连接更新：2026-09-23；原生 Hermes 对话更新：2026-09-27。本文描述托管实现；接手时的缺陷、被否定的旧 CLI 出站路径见 [阶段 0 review](hermes-phase0-review.md)。制品来源、构建方式和发行边界见 [运行时制品](hermes-runtime-artifact.md)。

## 用户路径

在「远程控制 → 连接聊天工具」安装 Hermes 聊天组件，然后点击「添加渠道」选择渠道。组件从受信任清单按需下载，客户端不运行 pip/uv，也不依赖系统 Python。界面从组件能力快照生成平台和凭据字段；支持企业微信、Telegram、飞书、Discord、Slack。同一渠道也可以添加多个账户，每个连接独立启停、编辑、移除和授权。其他 Hermes 平台保留在可搜索目录中，并显示缺少依赖或尚未接入的原因。

企业微信、Telegram 和飞书支持扫码创建；所有已接入渠道保留凭据表单，Discord、Slack 使用手动配置与官方配置入口。Telegram 使用 Hermes 官方机器人创建服务，界面在生成前显示该服务边界。企业微信流程为：

1. 点击生成二维码，用企业微信扫描，按企微页面完成机器人创建。
2. 官方接口返回完整 Bot ID 与 Secret 后，CCEM 后端自动加密保存凭据、启动新连接；无需抄写凭据。连接进入运行状态后自动打开本人账号配对窗口。
3. 在与机器人的本人私聊中发送桌面显示的 `/ccem connect <nonce>`。桌面显示平台原生的发送者、聊天和账号代次；用户确认身份后完成配对；工作区权限可选，也可稍后单独配置。

机器人连接成功不等于工作区已授权。企业微信接口不提供可信的扫码者身份；Telegram 返回的 owner_user_id 也不自动转成工作区授权。所有渠道都需私聊口令和桌面批准，配对窗口为 120 秒，仅接收有真实原生消息 ID 的本人私聊，不接受群聊和线程。窗口过期后可重新连接本人账号。

手动配置保留在独立入口：填写平台所需字段、保存配置并建立连接，然后打开本人账号配对。未配置时可以切回扫码创建；从等待扫码切到手动配置会先取消当前扫码会话。

扫码会话的本地有效期为 300 秒；Telegram 服务端期限更短时以较早者为准。生成或等待期间可取消；等待时可刷新二维码，过期后可重试。取消、替换和过期后，旧会话的迟到结果不能保存凭据。关闭设置页面不会自动取消后台会话。完整凭据被接受后新增独立连接，保留其他连接及授权；连接中仍可从连接卡片停止或移除。本地取消或过期不会删除已经在平台侧创建的机器人。

配对后可直接与 Hermes 聊天，不必绑定工作区或接管 CCEM 会话。在机器人详情中选择独立的对话模型，使用已有的 Anthropic Messages 兼容 API 环境；该选择与会话接管的通知模型分别保存。普通消息由原生 Gateway/AIAgent 处理，保留对话历史和记忆，不再一律重写为 CCEM 任务输入。

需要查询或继续授权任务时，Hermes 可调用 CCEM 工具；继续任务先生成冻结正文的预览，尚不执行。唯一待确认操作的预览取得平台发送回执后，用户另发一条「确认」才提交，也可回复「取消」。提前到达的确认、重复消息和授权代次变化不能转成一次新的执行。显式聊天命令仍保留如下。Slack 在普通私聊中使用 `!ccem` 前缀，以避开平台原生 slash command；其他渠道使用 `/ccem`。界面显示并复制对应平台的前缀。

| 命令 | 行为 |
| --- | --- |
| `/ccem list` | 授权工作区或已接管会话中的最近 20 个任务 |
| `/ccem status <runtimeId>` | 当前任务状态 |
| `/ccem events <runtimeId> [cursor]` | 分页事件及原始游标，报告缺失/损坏历史 |
| `/ccem input <runtimeId> <text>` | 冻结输入正文，返回待确认内容，尚不执行 |
| `/ccem confirm <challenge>` | 另一条原生消息确认后，至多提交一次 |
| `/ccem cancel <challenge>` | 撤销尚未提交的确认 |
| `/ccem operation <operationId>` | 查询这次输入的实际执行状态 |

输入正文最多 2000 UTF-8 字节；Discord 收紧为 1400 字节，为完整确认预览预留消息空间。超长输入在创建操作前拒绝，确认预览不截断正文。确认有效期 120 秒。重复确认返回同一操作；同一原生请求 ID 携带不同正文会拒绝。停止或撤销授权不等于取消已交给 provider 的任务。

## 当前会话交给机器人

Workspace composer 右下角「发送/继续 → 交给机器人」选择已配对的聊天与一个已有 API 环境。机器人只获得当前 native runtime 的访问和确认后输入权限，不要求工作区授权，也不扩大原配对的工作区范围。接管后输入框旁显示机器人，点开可更新或解除；旧版企微任务卡保留在对话框次入口。

Hermes 使用接管时所选环境的 Anthropic Messages 接口判断值得推送的进展、完成、阻塞或问题；普通工具活动与重复结果可以静默。该通知判断进程不能运行工具或执行任务。用户回复由 Hermes 结合聊天历史和近期已送达通知处理；只有请求继续任务时才准备输入预览，目标不明确时先澄清，也可用 input 命令指定。另一条确认消息才继续原 CCEM 会话，桌面仍可继续操作。详细约束和验收见 [会话接管](hermes-session-handoff.md)。

## 所有权与边界

- CCEM 拥有任务、工作区授权、确认、操作账本和出站账本；Hermes 拥有平台 SDK、连接、原生身份、对话、记忆与工具调用循环。
- Hermes 固定源码 `bc1330eebc0aa8a443501b5f62586eb7361353a5`，叠加 [通用网关契约补丁](../../scripts/hermes/patches/0001-managed-gateway-contracts.patch) 与 [托管原生对话补丁](../../scripts/hermes/patches/0002-native-managed-conversations.patch)。补丁提供鉴权后不可变命令上下文、逐消息分发和复用当前连接的严格发送。
- 2026-09-27 起，原 integration-only 网关已替换为托管原生 Gateway/AIAgent。对话历史、记忆及 Agent profile 按 `routeId + generation` 的 scope 隔离，不恢复用户独立 Hermes 的会话。工具白名单为 `memory`、`skills_list`、`skill_view` 和 `ccem_list`、`ccem_status`、`ccem_events`、`ccem_prepare`；不开放终端、任意文件操作、MCP 或模型直接确认执行。CCEM 工具调用及最终回复均复验当前 scope，最终回复经 CCEM outbox 投递。
- 会话通知仍另起隔离、限时、无工具的 Hermes AIAgent 判断进程，不加载对话记忆或用户上下文。模型凭据只经私有进程通信提供并在内存中使用，不写入 profile 配置，不复用 OAuth 或用户 Hermes profile；用户原有 Hermes 源码、配置和服务与该组件分离。
- 每个连接持有独立私有 profile、Hermes 进程和桥令牌，共享经过验证的运行包。令牌按子进程生命周期生成，只经私有 stdin 传入，不传全权限控制描述文件。每个令牌绑定 accountRef；能力发现进程没有任务操作权限。外部控制面只接受固定的 `ccem.bridge.*` 方法，执行前再次验证令牌、账户和授权代次。
- 渠道凭据按既有 CCEM 加密机制保存，状态接口只返回已配置字段名。编辑保留 accountRef；仅改名保留授权，修改凭据撤销该连接旧授权并轮换进程令牌。停用保留授权，移除撤销该连接授权和待发通知。旧单连接配置在同一 SQLite 事务中迁移，保留 accountRef、密文和授权；失败可重试，不重新绑定旧账户。
- 扫码创建由私有 host 调用固定的企业微信或 Hermes Telegram 创建服务 HTTPS 接口，拒绝重定向，单次请求最多 8 秒、响应最多 64 KiB。扫码状态可携带渲染所需的二维码地址，不携带轮询码或渠道凭据；错误只返回固定脱敏代码。成功响应缺少任一凭据都会失败，不会补用其他机器人的字段。
- 工作区以真实 canonical 路径校验，不接受字符串前缀作为授权；目录符号链接改指向后授权失效。

## 执行与投递

确认在调用 native runtime 前持久化 submitting。helper 为每次实际 provider 调用生成独立 invocation ID，记录该调用包含的 client message IDs；只有同一 runtime、同一实际调用的终态可以完成操作。普通 ready、任意会话完成或相同 client ID 的另一次调用均不能冒充完成。

崩溃时正在提交/执行但未证明终态的操作恢复为 unknown，不自动重提。后续拿到同一实际调用的可信终态可以更新；发现同一操作对应多次调用则保持歧义。

SQLite 以同一事务保存事件游标、当前输入归属和待发通知。远程输入的操作通知抑制本次输入的泛化完成通知；随后本地新输入仍可收到自己的完成通知。轮询和投递按连接独立执行，停止或异常的连接不会占满其他账户的待发队列。单个 runtime 的缺失或损坏历史不会阻塞其他任务或已落账的通知。

发送前先把 outbox 写为 sending。Hermes 严格发送复用精确 profile 的当前连接，不临时启动第二个发送器，不改投默认聊天/父线程。企业微信仅做一次主动私聊发送；请求 ACK 保存为 receiptId，不伪造为 messageId。模糊超时或崩溃恢复为 unknown，不自动补发；sent 表示平台回执确认，不表示用户已读。
