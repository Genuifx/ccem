# CCEM 托管 Hermes 集成

实现日期：2026-09-10。本文描述托管实现；接手时的缺陷、被否定的旧 CLI 出站路径见 [阶段 0 review](hermes-phase0-review.md)。制品来源、构建方式和发行边界见 [运行时制品](hermes-runtime-artifact.md)。

## 用户路径

在「远程控制 → 连接聊天工具」安装 Hermes 聊天组件。组件从受信任清单按需下载，客户端不运行 pip/uv，也不依赖系统 Python。界面从组件能力快照生成可用平台和凭据字段；当前验证包提供企业微信，未包含依赖或未支持严格投递的平台不可选。

保存渠道配置并建立连接后，点击连接本人账号，在本人私聊发送桌面显示的 `/ccem connect <nonce>`。桌面显示平台原生的发送者、聊天和账号代次；用户选择已有工作区、是否接收通知、是否允许确认后继续任务，再批准。配对窗口 120 秒，仅接收有真实原生消息 ID 的私聊。

聊天命令：

| 命令 | 行为 |
| --- | --- |
| `/ccem list` | 最近 20 个授权工作区内的任务 |
| `/ccem status <runtimeId>` | 当前任务状态 |
| `/ccem events <runtimeId> [cursor]` | 分页事件及原始游标，报告缺失/损坏历史 |
| `/ccem input <runtimeId> <text>` | 冻结输入正文，返回待确认内容，尚不执行 |
| `/ccem confirm <challenge>` | 另一条原生消息确认后，至多提交一次 |
| `/ccem cancel <challenge>` | 撤销尚未提交的确认 |
| `/ccem operation <operationId>` | 查询这次输入的实际执行状态 |

输入正文最多 2000 UTF-8 字节，确认预览显示完整正文。确认有效期 120 秒。重复确认返回同一操作；同一原生请求 ID 携带不同正文会拒绝。停止或撤销授权不等于取消已交给 provider 的任务。

## 所有权与边界

- CCEM 拥有任务、工作区授权、确认、操作账本和出站账本；Hermes 拥有平台 SDK、连接、原生身份与消息传输。
- Hermes 固定源码 `bc1330eebc0aa8a443501b5f62586eb7361353a5`，叠加 [通用网关契约补丁](../../scripts/hermes/patches/0001-managed-gateway-contracts.patch)。补丁提供鉴权后不可变命令上下文、独立命令分发和复用当前连接的严格发送。
- 托管 profile 启用 integration-only：不调用模型兜底、不运行工具/cron、不恢复用户独立 Hermes 的会话。用户原有 Hermes 源码、配置和服务与该组件分离。
- 桥令牌按子进程生命周期生成，只经私有 stdin 传入；不传全权限控制描述文件。外部控制面只接受固定的 `ccem.bridge.*` 方法，且在执行前再次验证令牌与授权代次。
- 渠道凭据按既有 CCEM 加密机制保存，状态接口只返回已配置字段名。配置变更创建新 accountRef 和私有 profile，旧授权全部撤销。
- 工作区以真实 canonical 路径校验，不接受字符串前缀作为授权；目录符号链接改指向后授权失效。

## 执行与投递

确认在调用 native runtime 前持久化 submitting。helper 为每次实际 provider 调用生成独立 invocation ID，记录该调用包含的 client message IDs；只有同一 runtime、同一实际调用的终态可以完成操作。普通 ready、任意会话完成或相同 client ID 的另一次调用均不能冒充完成。

崩溃时正在提交/执行但未证明终态的操作恢复为 unknown，不自动重提。后续拿到同一实际调用的可信终态可以更新；发现同一操作对应多次调用则保持歧义。

SQLite 以同一事务保存事件游标、当前输入归属和待发通知。远程输入的操作通知抑制本次输入的泛化完成通知；随后本地新输入仍可收到自己的完成通知。单个 runtime 的缺失或损坏历史不会阻塞其他任务或已落账的通知。

发送前先把 outbox 写为 sending。Hermes 严格发送复用精确 profile 的当前连接，不临时启动第二个发送器，不改投默认聊天/父线程。企业微信仅做一次主动私聊发送；请求 ACK 保存为 receiptId，不伪造为 messageId。模糊超时或崩溃恢复为 unknown，不自动补发；sent 表示平台回执确认，不表示用户已读。
